Loops
EZ provides four loop constructs covering all common iteration patterns. Use escape to break and skip to continue.
while — condition loop
while x > 0 { out x x -= 1 }
repeat...to — numeric range loop
# Basic: 0 to 9 repeat i = 0 to 9 { out i } # With step (NEW) — every 2 repeat i = 0 to 10 step 2 { out i # 0, 2, 4, 6, 8, 10 } # Negative step — countdown repeat i = 10 to 0 step -1 { out i # 10, 9, 8 ... 0 }

escape & skip — break & continue
repeat i = 0 to 10 { when i == 3 { skip } # continue — skip 3 when i == 7 { escape } # break — stop at 7 out i } # prints: 0, 1, 2, 4, 5, 6

Functions (Tasks)
Functions are called tasks in EZ. They support closures, default parameters, variadic args, lambdas, TCO, and optional type annotations.
Basic Tasks
# Basic task task greet(name) { out `Hello, {name}!` } # With type annotations task add(a: int, b: int) -> int { give a + b } # Default parameters task power(base, exp = 2) { give pow(base, exp) } power(3) # → 9 power(2, 8) # → 256 # Variadic task sumAll(...nums) { total = 0 get n in nums { total += n } give total } sumAll(1, 2, 3, 4) # → 10
Lambdas
# Single expression lambda double = |x| x * 2 # Multi-param lambda add = |a, b| a + b # Lambda with body block process = |x| { result = x * 2 when result > 100 { result = 100 } give result } # Typed lambda square = |x: int| -> int x * x # Higher-order functions nums = [1, 2, 3, 4, 5] evens = filter(nums, |x| x % 2 == 0) doubled = map(nums, |x| x * 2)
Closures & Static Locals
# Closures capture surrounding scope task makeCounter() { count = 0 give || { count += 1 give count } } counter = makeCounter() out counter() # 1 out counter() # 2 # Static local — persists across calls task inc() { static x = 0 x += 1 give x } inc() # 1 inc() # 2
Tail Call Optimization
⚡
TCO is built-in — recursive tail calls are automatically optimized. Recursion to 20,000+ levels works without stack overflow.
# This won't overflow — TCO kicks in automatically task factorial(n, acc = 1) { when n <= 1 { give acc } give factorial(n - 1, n * acc) # tail call }

Async & Concurrency
EZ provides cooperative async/await on a single-threaded event loop, plus OS-level thread spawning for true parallelism. Atomics and mutexes for shared state.
async / await
# Define an async task async task fetchData(url) { response = await http.get(url) give response.body } # Await a future async task main() { data = await fetchData("https://api.example.com") out data } # Async lambda worker = async |url| { give await http.get(url) }
spawn — OS Threads
# spawn creates a real OS thread # Each thread gets its own VM instance future = spawn(|| { # Heavy computation in background result = 0 repeat i = 0 to 1000000 { result += i } give result }) doOtherWork() # runs while thread runs result = await future # block until thread done out result
Mutex & Atomic
# Mutex for shared state m = mutex() shared = 0 task increment() { lock(m) shared += 1 unlock(m) } # Atomic counter counter = Atomic(0) counter.increment() counter.add(5) out counter.get()

Type System
EZ has an optional gradual type system. Unannotated code stays dynamic. Annotated code is checked at compile time. any is the implicit type for unannotated variables.
Primitive Types
int
x: int = 42
float
x: float = 3.14
string
x: string = "hi"
bool
x: bool = true
nil
x: nil = nil
any
x: any = anything
Generic Types
# Typed arrays nums: Array[int] = [1, 2, 3] names: Array[string] = ["Ali", "Sara"] # Typed functions task process(items: Array[int]) -> int { total = 0 get x in items { total += x } give total } # Instance type task greetPerson(p: Person) -> string { give p.greet() }
How Gradual Typing Works
# Unannotated — any, no checking, works as before x = 5 x = "now a string" # fine # Annotated — type checked at compile time y: int = 5 y = "string" # TYPE ERROR: string not assignable to int # Function with annotations — checked task double(n: int) -> int { give n * 2 } double("hello") # TYPE ERROR: string not assignable to int # Unannotated — not checked, any goes anywhere task process(x) { give x + 1 # no check on x }
✅
any is contagious — if either operand in an operation is any, the result is any. This lets unannotated code flow freely through typed code at boundaries.

Design by Contract
EZ implements Design by Contract (DbC) with requires (preconditions), ensures (postconditions), and old() for capturing pre-call values. Disable with --no-contracts.
requires & ensures
task divide(a, b) requires b != 0, "Cannot divide by zero" requires a >= 0, "Numerator must be non-negative" ensures result >= 0, "Result must be non-negative" { give a / b } divide(10, 2) # → 5 ✓ divide(10, 0) # Error: Precondition failed: Cannot divide by zero
old() — Capture Pre-call Values
# old() captures the value of an expression BEFORE the function runs task withdraw(balance, amount) requires amount > 0, "Amount must be positive" requires amount <= balance, "Insufficient funds" ensures result == old(balance) - amount, "Balance must decrease exactly" { give balance - amount } out withdraw(100, 30) # → 70 ✓ withdraw(50, 200) # Error: Precondition failed: Insufficient funds
Multiple Clauses
task clamp(value, lo, hi) requires lo <= hi, "lo must be <= hi" requires value >= lo, "value below minimum" requires value <= hi, "value above maximum" { give value }
🛡️
requires — checked when the function is called. Failure means the caller is at fault.
⚠️
ensures — checked when the function returns. Failure means the implementation is at fault.
⚡
--no-contracts — run with ez file.ez --no-contracts to strip all contract checks for production performance. Contracts add zero overhead when disabled.

Foreign Function Interface (FFI)
EZ can load any Windows DLL and call its functions directly. Crash-protected via SEH/VEH — a bad native call won't kill the EZ process.
Loading & Calling DLLs
# Load a DLL handle = os_load_lib("sqlite3.dll") # Get a function pointer fn_open = os_get_func(handle, "sqlite3_open") # Call it — return type first, then args result = os_call(fn_open, "int", db_path, db_handle_ptr) # Windows API example kernel32 = os_load_lib("kernel32.dll") beep_fn = os_get_func(kernel32, "Beep") os_call(beep_fn, "int", 1000, 500) # 1000Hz for 500ms
Memory Management
# Allocate raw memory for FFI buf = os_alloc(256) # Write / read values os_write_byte(buf, 0, 42) os_write_uint64(buf, 0, 12345678) val = os_read_uint64(buf, 0) # Always free when done os_free(buf)

Decorators new
EZ has six built-in decorators that add cross-cutting behaviour to tasks and models — caching, rate limiting, audit logging, persistence, snapshots, and validation. Zero boilerplate.
@cached — Memoize method results

The result is stored on the instance. Subsequent calls return the cached value without re-executing the body. Ideal for expensive computed properties.

model Report { init(data) { self.data = data } @cached task compute() { total = 0 get x in self.data { total += x } give total } } r = Report([1,2,3,4,5]) out r.compute() # computes once → 15 out r.compute() # returns cached 15
@ratelimit(n, "unit") — Throttle call frequency

Limits the task to at most n calls per time unit. Throws RateLimitError with retry-after ms if exceeded. Units: "second", "minute", "hour", "day".

@ratelimit(5, "minute") task sendEmail(to, subject, body) { # Max 5 calls per minute — auto enforced } @ratelimit(100, "second") task apiCall(endpoint) { give http.get(endpoint) }
Model Decorators
@audited

Every property write is logged to an audit trail with timestamp and old/new values automatically.

@audited model BankAccount { init(b) { self.balance = b } } # balance changes auto-logged
@snapshot

Captures model state on each mutation enabling undo via restore().

@snapshot model Editor { init() { self.text = "" } } e.restore() # undo last change
@persist("file") — Automatic persistence

Model state is saved to a JSON file on every property write and restored at startup. Zero-code persistence.

@persist("settings.json") model AppSettings { init() { self.theme = "light" self.fontSize = 14 } } settings = AppSettings() settings.theme = "dark" # → saved to settings.json # Next program run: theme is still "dark"
💡
Decorators are compiled — not runtime wrappers. @ratelimit emits a RATELIMIT_CHECK opcode at function entry. @cached emits GET_CACHED_RESULT/STORE_CACHED_RESULT around the body. Zero reflection overhead.

v2.0 Changelog
What's New in v2.0
Deep analysis of the latest commit reveals 9 new features, 8 significant improvements, and 3 new source files totalling ~1,300 new lines of C++ compared to the original build.
New Features
✨ Template Strings

Backtick `Hello {name}!` with full expressions in {}. Nested calls, arithmetic, and string methods all work inside the braces.

🔗 ?? and ?. Operators

?? returns the left side if it's not nil, otherwise the right. ?. safely chains property access — returns nil if any link in the chain is nil.

🔢 Tuples & Destructuring

Native tuple values via (1, "hi", 3.14). Unpack with (a, b, c) = t. Functions can return multiple values cleanly without wrapping in arrays.

🏷️ Keyword Arguments

Pass arguments by name in any order: Add(y=4, x=3). The language automatically maps named arguments to the correct parameter positions.

📐 struct Keyword

Define lightweight data structures with typed fields and defaults. Structs are simpler than models — no methods, no inheritance, just fast value containers.

🧩 interface & implements

Define contracts using interface and enforce them with implements. Models can implement multiple interfaces. Verified at compile time.

📌 static Variables

static inside a task persists its value across calls — like a function-level memory. Useful for counters, caches, and lazy initialization.

🚶 repeat...step

repeat i = 10 to 0 step -1 counts down. step 2 skips every other. Step can be any expression — positive, negative, or computed at runtime.

💾 Script Caching (.ezc)

Compile your script with ez file.ez --compile to save a .ezc binary. Run it directly with ez file.ezc for instant startup with no re-parsing.

🎨 6 Decorators

@cached, @ratelimit, @audited, @snapshot, @persist, @validate — add caching, throttling, logging, undo, persistence, and validation with a single line.

🐞 Better Error Messages

Errors now show the exact source line with a ^^^ caret pointing to the problem. Contract failures print the actual values of local variables at the moment of failure.

Improvements
🛡️ FRAMES_MAX Enforced

Was declared (512) but never checked. dispatchCall() now throws a clean Stack overflow error instead of silently exhausting OS stack memory.

📍 Source Snippets in Errors

EZ_RegisterSource() stores source lines at load time. Runtime errors now print the fault line with ^^^ caret. Contracts show local variable values at failure.

🧵 Rope Strings (EZConcatString)

String + now builds a lazy tree instead of allocating immediately. Only flattened on demand. Eliminates O(n²) string building. 10,000 concatenations now takes milliseconds.

🔤 ShortString Inline (14 bytes)

Strings ≤14 bytes stored inline in the Value variant — no heap allocation, no shared_ptr. Property names, short identifiers, keywords all benefit.

🛡️ Contract old() Support

Pre-call value capture fully implemented. Compiler scans ensures clauses for old(), emits captures into hidden locals at function entry, substitutes them in postcondition checks.

⚙️ --no-contracts Flag

Global g_disableContracts strips all contract compilation. Zero overhead in production. Works with ez run and ez bundle.

🔍 --dump / --ezasm

New CLI flag dumps human-readable bytecode disassembly for every function. Shows opcode names, operands, and constant pool values. Invaluable for debugging.

🏗️ MiniJson.h

New lightweight header-only JSON parser/builder. Used internally by @persist. No external dependency — pure C++ with full object/array/string support.
